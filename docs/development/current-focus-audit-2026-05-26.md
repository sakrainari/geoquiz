## 差分整理

### 1. README の公開ブランチ表記が現状とズレている

- `README.md` には `GitHub Pages: main / root で公開` とある
- 実際の作業ブランチは `master`
- 公開設定が本当に `main / root` なのか、過去記述の残骸なのかを確認したい

対応候補:

- GitHub Pages の実設定を確認して README を修正
- もし `master / root` 運用なら明記を直す

### 2. README の「市外局番（広域）」が現行 UI と一致していない

- `README.md` の機能一覧には `市外局番（広域）` がある
- ただし `js/quiz-modes.js` の公開モード定義には専用の `ma_broad` のようなモードが見えない
- `index.html` の開始導線にも広域市外局番専用モードは見当たらない
- `maBroadFeatures` は README と計算済みデータの説明には残っている

見立て:

- 3桁までの広域市外局番専用モードは、過去に検討または検証されたが現方針では採用していない
- 現在は 5 桁までの通常市外局番モードを主として扱う
- 他サイトで 3 桁モードを扱うものが多く、GeoQuiz での優先度は低い

対応候補:

- README では「過去検証用データが残っている」程度に表現を弱める
- 専用モードとしては扱わない方針を明文化する

### 3. `japan_all` 周辺の文書がコードより先行している

- `README.md` に `全国モード（japan_all）のパフォーマンス改善` とある
- `CHANGELOG.md` に `japan_all`, `preferCanvas`, `forceLiteMode` の記述がある
- `docs/vectorgrid-migration-plan.md` は `japan_all` を前提にかなり具体的
- `tools/build-japan-all-data.mjs` も存在する
- しかし現行の `data/catalog.js` には `japan_all` が存在しない

見立て:

- `japan_all` は文書だけ先行しているのではなく、一度実装と検証が行われた形跡がある
- ただし処理が重すぎてプレイ困難だったため、現行 `master` では `catalog.js` から外されている

対応候補:

1. `japan_all` を現行スコープから外すなら、README / CHANGELOG / vectorgrid 文書に「構想段階」や「未反映」を明記
2. `japan_all` を戻すなら、`catalog.js` まで含めて現行コードに再接続

### 4. 広域データセット全般が重いわけではない

現時点で、以下の広域データセットは問題なくプレイできている。

## 軽さの論点

### 1. 現行コードにある最適化スイッチが catalog 側でほぼ使われていない

- `js/map-renderer.js` には `preferCanvas` 対応がある
- `js/app.js` は `appConfig.forceLiteMode` を読む
- しかし現行 `data/catalog.js` に `preferCanvas` / `forceLiteMode` の設定は見当たらない

見立て:

- 最適化の器はあるが、現行データセット設定に反映されていない

確認したいこと:

- 大きいデータセットでこのフラグを本当に使う想定か
- 使う前提で文書だけ進んだのか

### 2. Firebase ランキングが初期画面から常時関与している

- `index.html` で Firebase のモジュールを直接読み込んでいる
- TOP 画面にグローバルランキング欄があり、取得処理も存在する
- ネットワーク不安定時やローカル確認時の体感に影響しうる

見立て:

- 「クイズ本体の重さ」と「ランキング取得の待ち」が混ざって感じられる可能性がある

確認したいこと:

- ランキング欄が初回表示の体感をどれだけ悪化させるか
- Firebase 未接続時のフォールバック文言と待ち時間が適切か

### 3. 現行で本当に重い候補を再確認する

現時点のユーザー確認では、広域データセットは概ねプレイ可能。
そのため「広域だから重い」と決め打ちせず、差が出る条件を改めて見る。

- `hokkaido_all`
- `kyushu_all`
- `kanto_all`
- `tokyo_all`
- 可能なら将来復帰候補としての `japan_all`

見る観点:

- 初回表示
- パン・ズーム
- hover 時の引っかかり
- クリック応答
- リザルト画面遷移
- Lite Mode 時の差
